Write all prose in ASD-STE100 Simplified Technical English. Obey these rules.

## Words

- Use one word for one meaning. Do not use a second word for the same thing.
- Use each word in one part of speech only. If a word is a noun, do not use it as a verb.
- Use the simplest word that is correct. Write "use" and not "utilize". Write "start" and not
  "initiate". Write "before" and not "prior to". Write "about" and not "approximately".
- Do not use words that are not necessary. Delete "please", "simply", "just", "actually" and
  "basically".
- Do not use slang, idioms, jargon or humor.
- Technical names and technical verbs are always permitted. Write them the same way each time.
- Do not make a group of more than three nouns. Write "the cache of the descriptor pool" and not
  "the descriptor pool cache configuration value".

## Sentences

- A sentence that gives an instruction has a maximum of 20 words.
- A sentence that gives information has a maximum of 25 words.
- Write one instruction in one sentence. If there are two instructions, write two sentences.
- Use the active voice. Write "the server reads the file" and not "the file is read by the server".
- Use simple verb tenses: the present, the simple past, and the future.
- Do not use the -ing form of a verb, unless the word is a technical name.
- Keep the article. Write "the build fails" and not "build fails".
- Put the words in this sequence: subject, verb, object.

## Text

- A paragraph has a maximum of six sentences.
- Give one topic in one paragraph. Put the topic in the first sentence.
- Use a vertical list when you give more than two conditions or more than two steps.
- Write steps in the sequence in which the reader must do them.
- Put a warning or a caution before the step to which it applies. Start it with a command.

## Code and identifiers

These rules apply to prose. They do not apply to code.

- Do not change code, file paths, commands, error text, identifiers or output. Copy them exactly.
- Comments and commit messages in the code also obey the rules above.
- Do not change the name of a function or a variable to make it more simple.
